# Самоаудит ZIKR 1.0 перед TestFlight

Дата: 2026-11-21. Аудит первой полной версии, написанной по итогам аудита 0.3.0. Две части: моя самокритика по продукту и независимая построчная проверка кода (отдельный проход, без доступа к компилятору).

## 0. Главное ограничение

**Код не компилировался и не запускался.** В облачной среде нет macOS/Xcode, а установка Swift-тулчейна для Linux была заблокирована политикой безопасности. Проверено то, что можно проверить без компилятора: синтаксис и ссылочная целостность `project.pbxproj` (собственный парсер), все plist/JSON, покрытие ключей локализации (скрипт), логика движка по тестам «в голове». Первая сборка в Xcode почти наверняка выдаст несколько ошибок компиляции: это нормальный этап, а не признак плохой архитектуры. Поэтому `scripts/testflight.sh` сначала прогоняет тесты и только потом архивирует.

## 1. Самокритика по продукту

| # | Проблема | Серьёзность | Решение |

## 2. Независимая проверка кода

Отдельный проход прочитал все Swift-файлы (~6,5 тыс. строк), plist, генератор проекта и сам `project.pbxproj`. Все находки ниже сверены с кодом и исправлены.

| # | Находка | Как исправлено |
|---|---|---|
| C1 | **Ошибка компиляции:** `ItemRef.id` объявлен дважды (поле UUID и вычисляемое в расширении) | Расширение оставлено пустым: UUID уже удовлетворяет `Identifiable` |
| C2 | Локальная переменная `number` затеняла функцию `number` | Переименована |
| R1 | Live Activity устаревала после нажатий в виджете или Пункте управления: интенты выполнялись в процессе виджета, где обновлять Live Activity нельзя | `IncrementIntent`/`UndoIntent` стали `LiveActivityIntent` и выполняются в процессе приложения. Плюс Live Activity обновляется после любой подгрузки внешних изменений |
| R2 | Гонка при перепланировании напоминаний: старая задача могла вернуть удалённое напоминание | Задачи выстроены в цепочку и всегда берут актуальные данные |
| R3 | Алерты не появлялись поверх листов и ночного режима (например, «уведомления запрещены») | Общий модификатор `storeAlert()` на всех листах и в ночном режиме |
| R4 | Импорт v3: без санитизации (интервал 0 → деление на ноль), исходный файл перезаписывался, в истории исправлений неверное «было» | Санитизация после конвертации, копия `pre-migration-v3-*.json` перед первой записью, правильное «было», защита от деления на ноль в UI |
| R5 | `refreshForNewDay()` ничего не делал: `@Observable` в Swift 6.2 не уведомляет при записи равного значения | Отдельный счётчик `dayRefresh`, который читают экраны. Проверка смены дня также при каждом возвращении в приложение |
| R6 | Если повреждённый файл не удалось отодвинуть, восстановление из автокопии и «начать заново» не работали (бесконечные повторы записи) | `replace` пишет без чтения старого файла. «Начать заново» сначала отодвигает файл |
| R7 | Отмена в длинном шаге (>500 нажатий) списывалась с сегодняшнего дня. Завершение программы нельзя было отменить. Кнопка на экране блокировки при битом ID нажимала другой счётчик | Нажатия программы хранятся сжатыми сериями «день → количество» без лимита. Последнее завершение можно отменить. Битый ID → ошибка, а не чужой счётчик |
| R8 | Приложение перечитывало файл после каждой своей записи; синхронная запись на главном потоке при уходе в фон; ночной режим сбрасывал «не гасить экран»; при неверной App Group данные молча разъезжались | Своё уведомление больше не шлётся; запись в фоне с `beginBackgroundTask`; после ночного режима действует 2-минутная пауза; в Настройках предупреждение, если App Group не настроена |
| — | Мёртвый код: интент выбора счётчика не подключён, флаг «завершено» в Live Activity не использовался | Виджет переведён на `AppIntentConfiguration`, Live Activity показывает «Программа завершена» |

Проверка подтвердила как корректные: требования AppIntents, ControlWidget, ActivityKit, структуру проекта (синхронизированные папки, встраивание расширения, подпись, тестовый хост), приватность (нет API с обязательной причиной), отсутствие религиозных текстов во всех строках и коде.

## 3. Что осталось за владельцем

1. **Первая сборка в Xcode 26** и исправление возможных мелких ошибок компиляции (см. раздел 0).
2. `./scripts/configure.sh` со своим Team ID и Bundle ID; создать запись приложения в App Store Connect.
3. Опубликовать `docs/privacy-policy.md` (например, GitHub Pages) и указать ссылки.
4. Решение по иконке (буква «Z» или вариант без буквы).
5. Вычитка узбекских текстов носителем.
6. Проверка на реальном iPhone: кнопка действия, Live Activity на экране блокировки, виджет, напоминания, восстановление из файла.
7. Уникальное название в App Store (например, «ZIKR: счётчик и программы»): короткое «ZIKR», вероятно, занято.

## 4. Дорожная карта после 1.0

- **1.1:** Apple Watch (касание, Digital Crown, двойное касание пальцами). Это главный аргумент против отказа 4.3.

- **1.3:** звуковой отклик, настраиваемые паттерны вибрации, экспорт статистики в CSV.
